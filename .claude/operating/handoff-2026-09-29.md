## 4. How Brian likes Claude to work

- **Open with the work.** No preamble.
- **Deliver complete files.** If a source file is missing, ask for it before starting.
- **Run a build start to finish in one pass.** In long sessions, at natural breaks
  between deliverables, remind Brian to check context usage.
- **Disagree openly** when a design is wrong: state the problem, why it matters, and the
  alternative.
- **Resuming a build across conversations:** open with the file's current state, the
  decisions made, and what is still open.
- **Honest uncertainty over polish.** If something could not be verified, say so
  plainly. Label each claim as run (show output), read (cite `file:line`), or assumed.
- **Root cause first** in changelog entries, reports, and commit messages.
- **Plain words.** Use the code's own names (env vars, functions, files). Do not invent
  labels. `CLAUDE.md` §Vocabulary has the few allowed shorthand terms.
- **Warn before spending NanoGPT tokens** (any live API call, `probe-context.py`, etc.).
- **Merge green work to `main` without asking** once the full check is green
  (`git push origin <branch>:main`, fast-forward only). Deploys pull from `main`.
- Subagents are pre-approved for broad or parallel work; not required for small tasks.
- Out-of-scope problems: name them as follow-ups, keep them out of the diff.

## 8. Workflows that work well

- **Ship a bot change:** load `repo-change-control` + `bot-code-invariants`; read the
  changelog; make the change with a test that calls the handler; bump `BOT_VERSION`; add
  the changelog entry; run `verify.sh`; merge to `main`; confirm CI green; give Brian the
  `vps-sync.sh` commands. The `ship` skill wraps this.
- **Live bot problem:** `repo-debugging-playbook` — get evidence (journalctl, `/errors`,
  `/audit`) before proposing a fix.
- **After any fix:** `fix-the-class` — find every other place the same bug shape occurs.
- **New check:** prove it goes red on the bad case before trusting its green
  (`add-regression-eval`).
- **Claims from an outside review or audit:** verify each before fixing
  (`verify-external-audit`).
- **End of session:** `session-debrief` — record lessons, decisions, and a handoff.

## 9. Mistakes Brian has corrected before (full list: `.claude/memory/constraints.md`)

- Running a host-specific command without confirming which host (VPS vs container).
- Calling a fix done when it was one instance of a wider bug class.
- Trusting a check that was never shown to fail. A verification that cannot fail proves
  nothing.
- Stating a theory as fact. Label it a theory until evidence arrives.
- Reverting a test edit with `git checkout -- <file>`, which destroyed uncommitted work.
  Re-edit instead.
- Editing by line number instead of by content; count an anchor's matches first.
- Treating a copied doc command as current; check it against the actual system.
- Trusting local `main` in a cloud session — it can be a stale, unrelated ref. Always
  compare against `origin/main`.
- A green test suite that asserted on source text instead of calling the handler (the
  `/features` crash, 2026-08-02). Tests must call the code.
- Agreeing with an explicit instruction but not checking the diff against its words.
- Sending a diagnostic message into a group chat — the characters see it as a real event.
