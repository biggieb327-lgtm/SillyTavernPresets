# Handoff — SillyTavernPresets / telegram-companion-bot

**Written 2026-08-08.** A map of the whole system: what it is, every doc, every skill,
every agent, and the machinery that enforces the rules.

## How to read this file

This is a **snapshot, and snapshots drift.** This repo has been burned by exactly that
before — a "quick reference" copy of the skill table drifted, omitted seven skills, and
misrouted a session (F1/F2 in `.claude/SCAFFOLDING-AUDIT-2026-07-30.md`). So:

**Authority order when this file disagrees with anything else:**

1. Runtime output (`=== STARTUP AUDIT ===`, `bash .claude/tools/verify.sh`) — always wins.
2. `CLAUDE.md`, `.claude/skills/skill-router/SKILL.md`, the skill bodies themselves.
3. This file.

Nothing here is pinned by an eval. Treat every number below as "true on 2026-08-08" and
re-derive it before relying on it. The *shapes* — what a skill owns, why a hook exists —
age much better than the counts.

**Read order for a first session:** `CLAUDE.md` → `.claude/OPERATING_MANUAL.md` → the
skill `skill-router` points you at. This file is the optional wide-angle view; you do not
need it to do a small task.

## 2. What the product actually is

A fleet of **seven Telegram companion-bot instances**, each an AI character with
persistent memory, running from **one shared `bot.py`**.

Instances differ only by three things: their directory, their `.env`, and their
SillyTavern `chara_card_v2` character card.

| Session | Directory | Card |
|---|---|---|
| `nora` | `/opt/telegram-bots/nora/` | `nora.json` |
| `bonnie` | `/opt/telegram-bots/bonnie/` | `bonnie.json` |
| `cass` | `/opt/telegram-bots/cass/` | `cass.json` |
| `emily` | `/opt/telegram-bots/emily/` | `emily_harper.json` |
| `priya` | `/opt/telegram-bots/priya/` | `priya.json` |
| `jules` | `/opt/telegram-bots/jules/` | `jules_nakagawa.json` |
| `marcus` | `/opt/telegram-bots/marcus/` | `marcus_calder.json` |

All seven run on a **VPS under systemd** as `bot@<instance>` (unit `deploy/bot@.service`,
`WorkingDirectory=/opt/telegram-bots/%i`), sharing one venv at `/opt/telegram-bots/venv/`
and one `bot.py` at `/opt/telegram-bots/bot.py`.

**The authoritative instance list is the set of `bot@<instance>` systemd units**, and the
authoritative instance name is the basename on the runtime `=== STARTUP AUDIT === …
Instance:` line — not the table above.

### Stack

- **Python 3.12** on Ubuntu 24.04. CI pins the same version; the `runtime-version-pinned`
  eval fails if `.github/workflows/evals.yml` and `CLAUDE.md` ever disagree — change both
  together.
- **`python-telegram-bot >=21.0,<22.0`** (async, job-queue). PTB v21's deprecated
  `asyncio.get_event_loop()` call is deliberately worked around in `main()` — don't
  remove it.
- **NanoGPT**, an OpenAI-compatible API at `https://nano-gpt.com/api/v1`.
- **SillyTavern `chara_card_v2`** JSON cards.
- Repo is **private since 2026-07-28** — anonymous `raw.githubusercontent.com` URLs 404.
  Any doc or script still telling you to `curl` one is stale by construction.

### Deployment

One command per instance, run **on the VPS as root**:

```bash
/opt/telegram-bots/.repo/telegram-companion-bot/deploy/vps-sync.sh <instance>
```

It fetches and hard-resets the checkout to `origin/main`, copies `preset.txt` + the
instance's preset layers + card + `bot.py` (compile-checked, `bot.py.bak` kept),
normalizes `CHARACTER_CARD`, restarts and enables the unit, then prints hash + STARTUP
AUDIT for verification. **Not curl-piped** — the repo is private.

Claude sessions cannot reach the VPS. You hand the owner commands; they paste output back.

**`/update` is dead as a deploy path.** The handler still exists but downloads over raw
URLs, so it fails `repo_not_readable` and replies telling the owner to run `vps-sync.sh`.
`update-all.sh` and `sync-cards.sh` are historical for the same reason.

## 4. Skills — all 21

**`.claude/skills/skill-router/SKILL.md` is the routing table. Consult it; don't guess.**

Only each skill's one-line description reaches a session for free. **Every body must be
explicitly loaded** — nothing here is preloaded, including the two that apply most often
(`repo-validation-gate`, `artifact-first-delivery`). Until 2026-07-30 the router claimed
otherwise, which suppressed exactly those two; the `skill-index-integrity` eval now
rejects any such exemption and checks the router table against `.claude/skills/` in
**both** directions.

Most skills share a shape: *When NOT to use → Procedure → Quality bar → Verification
checklist → Common mistakes → What to report back.* The "When NOT to use" section is not
filler; it's what keeps a skill from being loaded into work it doesn't govern.

### Always-consider

| Skill | Load when | What it owns |
|---|---|---|
| `skill-router` | Choosing a skill | The routing table. New skills must be registered here in the same change or they're invisible tomorrow. |
| `repo-validation-gate` | Before claiming **anything** done | "Done" is a claim about the world; back it with the world's testimony. Three gates: compile/parse, behavior (exercise the path, not just its syntax), regression (`run-evals.sh`). |
| `artifact-first-delivery` | Before deciding where any output goes | The deliverable is the file, not the message about the file. Test: **which file enforces this tomorrow?** In this repo, work isn't delivered until pushed. |

### Shipping `bot.py`

| Skill | Load when | What it owns |
|---|---|---|
| `repo-change-control` | **Before editing `bot.py`** for anything meant to reach the fleet | The end-to-end release procedure: read-first rules, `BOT_VERSION`, changelog, verification, merge to main, deploy handoff. |
| `bot-code-invariants` | Writing **or reviewing** any `bot.py` diff | The pass/fail code rules: concurrency, the output choke point, LLM-call budget, memory provenance, platform constraints. Rule #16 owns the kill-switch policy. |

## 5. Agents — all 11

Subagents are **pre-authorized by owner standing grant** (`CLAUDE.md` working principle
#6). In this repo, breadth or multiple parts *does* count as the user having asked. It is
not mandatory — prefer inline work when the task is small or the context is already
loaded. `.claude/hooks/agent-authorization.py` re-asserts the grant only on turns where a
server-side instruction would otherwise override it.

| Agent | Model | Mission | Hard scope limit |
|---|---|---|---|
| `chief-operator` | opus | Top-level orchestrator for multi-step work: understand → split into microtasks → dispatch → decide → patch → verify → handoff. | Delegates implementation, keeps decisions. Never accepts "done" without evidence. |
| `builder` | sonnet | Implement exactly **one** well-specified microtask with evidence. | Files named in the task plus their tests. Ambiguity or out-of-scope need → stop and report, don't improvise. |
| `coder` | sonnet | Code-only: write, edit, debug code and tests. | No research, deploys, docs prose, delegation, or GitHub/user-facing actions. |
| `qa-engineer` | sonnet | Independently verify a claimed-complete change; PASS/FAIL per criterion. | Verification only, fixes nothing. No acceptance criteria → first output is `UNVERIFIABLE`, nothing else. |
| `adversarial-critic` | opus | Attack the work product; find where it's less real than it claims. | Critique only. Standing questions: *which file enforces this tomorrow?* Is the evidence real output or a paraphrase? What was quietly narrowed? |
| `character-reviewer` | opus | Judge whether character content still reads as the character; triage voice defects to content vs. prompt-assembly code. | Loads `edit-cards-and-presets` first — that skill is authoritative on canon. |
| `eval-designer` | opus | Turn one observed failure into a permanent runnable check. | `.claude/evals/**` only. No root cause → sends it back; an eval built on a symptom pins the wrong thing. |
| `system-fixer` | sonnet | Surgical repairs to the operating machinery — agents, skills, hooks, evals, settings. | `.claude/**` only. Reproduce first (hooks run by hand from sample JSON), fix minimally, re-run to prove. |
| `improvement-analyst` | opus | Find the highest-leverage **system** patch from recurring friction. | Analysis + one proposal. Asks: what file, existing today, should have prevented occurrence #2 — and why didn't it? **Deletions count as patches.** |
| `context-librarian` | haiku | Keep the knowledge layer short, current, and true. | `.claude/memory/**`, `CLAUDE.md`, changelog *formatting* (never content). Flags contradictions; the chief resolves them. |
| `research-scout` | haiku | Answer one factual question from primary sources. | Read-only, changes no files. Always notes the date/version of what it cites. |

## 6. The enforcement machinery

This is the part that makes the rules real rather than advisory. Four layers.

### 6.1 Hooks — `.claude/hooks/`, wired in `.claude/settings.json`

Thirteen hooks. Three are `.sh` wrappers around a `.py` implementation
(`host-guard`, `handoff-guard`, `claim-guard`) — the shell file carries the scope and
rationale comment, the Python does the work.

| Event | Hook | What it does |
|---|---|---|
| SessionStart | `session-audit.sh` | Injects branch, uncommitted count, last operational-log row, and the repeat-mistake constraint list as session context. |
| UserPromptSubmit | `agent-authorization.py` | Restores the owner's standing subagent authorization when a server-side instruction would suppress it. |
| PreToolUse (Bash) | `risk-guard.sh` | Blocks a **short, precise** list of high-blast-radius commands. Exit 2 blocks and feeds stderr back. Kept short deliberately: a guard that misfires gets disabled, and then guards nothing. |
| PreToolUse (Bash) | `anchor-guard.sh` | Constraint C7's mechanical half — blocks in-place edits addressed by **line number** against a version-controlled file. |
| PostToolUse | `evidence-log.sh` | One line per tool call to a per-day evidence log. The delivery gate and `qa-engineer` read it to confirm verification actually ran. |
| PostToolUse | `budget-governor.sh` | Counts tool calls; nudges at thresholds. A governor, not a brake. |
| PostToolUse | `py-syntax-guard.sh` | Catches a Python file that stopped parsing **this turn**, instead of letting it surface three calls later as a confusing downstream failure. |
| Stop | `host-guard.sh` | Constraint C1 — confirm the host before a host-specific command. |
| Stop | `handoff-guard.sh` | C1 family — operator-handoff hygiene (C16: a handed-over command block must work on someone else's machine). |
| Stop | `claim-guard.sh` | C8 family — catches claiming two artifacts identical on metadata rather than a hash. |
| Stop | `delivery-gate.sh` | **The "no fake done" gate.** Blocks ending a turn with a modified `bot.py` lacking a `BOT_VERSION` bump, a changelog entry, compile evidence, or a test that *calls* any `*_cmd` the diff touched. |
| Stop | `eval-gate.sh` | Bounded retry loop: if this session's uncommitted work breaks the evals or pytest, feeds the failure back for another fix round. Bounded — N rounds, one escalation, then it stands aside so a turn can always end. |
| PreCompact | `handoff-writer.sh` | Writes a handoff snapshot before compaction so the post-compaction session inherits ground truth, not just a lossy summary. |

Each guard's header states its scope **honestly**, including what it cannot see. The
host/handoff guards say plainly that the fleet is on a machine this container can't reach,
so nothing in here can stop a wrong command the owner pastes by hand.

### 6.2 Evals — `.claude/evals/run-evals.sh`

38 checks, each pinning a real incident. Run in every session **and** in CI on every push.
Fast (<1s each) and dependency-free by design (bash + python3 only).

```bash
bash .claude/evals/run-evals.sh   # exit 0 = all PASS
```

They cluster into:

- **Crash/regression pins** — `streaming-error-body`, `heartbeat-alive`,
  `graceful-shutdown`, `venv-explicit-python`, `tzdata-pinned`, `bot-compiles`,
  `bot-imports`.
- **Leak guards** — `secret-scan`, `no-reasoning-content-leak`, `reasoning-leak-guard`,
  `document-reply-leak-guard-optout`, `wsdot-key-not-logged`, `no-exception-leak`.
- **Group-chat class guards** — `group-deliver-clean`, `group-cmd-allowlist`,
  `owner-claim-once`, `private-gate-registered`.
- **Memory-provenance guards** — `note-ownership-extraction`, `note-ownership-followup`,
  `note-confidence-gate`, `null-over-guess`.
- **Doc/config consistency** — `version-changelog-sync` *(currently RED)*,
  `env-vars-documented`, `skill-index-integrity`, `runtime-version-pinned`,
  `claude-md-refs-resolve`, `roadmap-claims-current`, `no-live-raw-urls`,
  `routine-prompts-runnable`, `cards-valid-json`, `settings-valid-json`,
  `shell-scripts-parse`.
- **Guards on the guards** — `gate-corpus`, `handlers-exercised`.

`SKIP` is a distinct outcome from PASS and FAIL: it means the check couldn't run *in this
environment* (here, `bot-imports` needs Pillow). It never happens in CI, which installs
requirements first. The suite says so loudly rather than lying in either direction.

### 6.3 Tools — `.claude/tools/`

| Tool | What it's for |
|---|---|
| `verify.sh` | **The standing verification block as one command.** Compile → pytest → evals → gate corpus → advisory sweep. ## 7. Memory layer

### `constraints.md` — C1–C20, mistakes made doing the work

Each entry carries a `seen` count, and **the count is the point** — it tells a future
session which constraints are load-bearing. At `seen: 2` a constraint **graduates**: it
stops being documentation and becomes a mechanism (a hook, a `sweep.py` scanner, an eval)
— or, when nothing mechanical could detect it, a section in the relevant skill.

The current repeat offenders, surfaced at every session start:

- **C1 (seen: 7)** — Confirm the host before any host-specific command.
- **C16** — A handed-over command block must work on someone else's machine.
- **C2** — Name the class before calling a fix done.
- **C3** — Prove a check RED before trusting its GREEN.
- **C7 / C17** — Anchor edits on content, not position; count an anchor's matches first.
- **C8** — Ask what a reading actually *measures* before concluding from it.
- **C12** — A command copied out of documentation is a claim about the past.
- **C13** — A verification command that cannot fail is not verification.
- **C14** — A scanner can't tell "this file does the bad thing" from "this file explains it."
- **C15** — Never `git checkout -- <file>` to revert a break-test edit; **re-edit instead.**
- **C18** — A break-test proves one assertion, not the whole check.
- **C19 / C20** (2026-08-07, newest) — Verifying "not reachable outside dispatch" proves
  reachability, not which jurisdiction covers the call; and a green test suite is not
  proof a reused pattern is safe at a *new* call site.

Slips you caught and fixed **mid-task** still get logged, in the **Minor** running log —
log them *because* they were self-corrected: they cost real minutes and nobody else ever
sees them.

### `operational-log.md` — the system failing

Format: **Date | failure | root cause | system patch | eval | next.** A row goes in once a
live-ops or code failure is root-caused and resolved — even when the fix was a doc or
guardrail change and nothing shipped to CI. An undocumented incident is one a future
session re-diagnoses from scratch.

The newest row (2026-08-07, `idea-scraper-actor`) carries a reusable lesson worth
repeating: **two independent sessions root-caused the same symptom to two different,
both-real bugs stacked on each other.** The first fix found didn't make the second less
real, and neither should have been called "the" fix without a live run proving items came
back.

### `routines.md` — four live scheduled Routines

| Routine | Schedule (UTC) |
|---|---|
| `ops-brief-daily` | `0 14 * * *` — daily, ~07:00 Pacific |
| `hygiene-check-weekly` | `0 9 * * 1` — Mondays |
| `improvement-loop-monthly` | `0 9 1 * *` — 1st of the month |
| `character-pass-monthly` | `0 14 15 * *` — 15th of the month |

**Rule: a change to a live Routine's prompt is mirrored in this file in the same session,
and vice versa.** A Routine that exists only in the scheduler, or only as prose, is
invisible and will drift — which has already happened once (a 2026-08-03 prompt update
went unwritten and was only backfilled 2026-08-07).

`send_later` one-shots are exempt; they're session-bound and self-disable.

Routines fire **unattended**, which is why `CLAUDE.md` working principle #1 exists:
**an unattended run never blocks on a question** — pick the most reasonable reading,
proceed, record the assumption in the output.

## 8. How to actually do work here

### Any `bot.py` change

1. Read `CHANGELOG.md` (root causes of every shipped fix).
2. Load `repo-change-control` **and** `bot-code-invariants`.
3. If it touches `GROUP_*`, `chat_id < 0`, or `handle_message` — load `group-chat-changes` first.
4. Make the change. Bump `BOT_VERSION`. Add a changelog entry, **root cause first**.
5. Add or extend a test that *calls* any `*_cmd` the diff touches — the delivery gate
   checks for a call, not a mention.
6. Run `bash .claude/tools/verify.sh`.
7. Apply `fix-the-class`: where else does this bug shape occur?
8. Merge to main by **pushing the branch ref**: `git push origin <branch>:main`.
9. Hand off the deploy per `deploy-and-verify-fleet` — seven `vps-sync.sh` invocations.

### Any content change (cards, seeds, presets)

Load `edit-cards-and-presets`. Remember `preset.txt` changes **all seven** bots, and that
`caa16137-nora.json` must never be synced with `nora.json`. Changelog and `BOT_VERSION`
are not required for pure content edits.

### A live bot misbehaving

Load `repo-debugging-playbook` **before** proposing any fix. Ask for the right evidence in
the right order. You cannot reach the VPS; every observation arrives because the owner ran
something and pasted it.

### Merging to main — the trap

```bash
git push origin <branch>:main
```

**Do not** `git checkout main` and merge there. A cloud session's local `main` can be a
stale branch with **no merge-base** against `origin/main`, and an eval suite run on it
reports a confident green about nothing (hit 2026-07-29 and again 2026-08-03; C13).
Always check `origin/main`, never local `main`.

### Owner policy on merging

Merge task branches to `main` autonomously once the full verification block is green
(owner decision, 2026-07-18). Any red = stop and report. A designated feature branch is
where you *develop*, not where work should stop — deploys and doc links pull from `main`,
so an unmerged branch ships nothing.

### New features

Default **ON**, with a mandatory env kill switch (unset = active, `0` = off). The kill
switch is required; default-on is the norm. Details in `bot-code-invariants` #16.

## 9. Traps, and things that are deliberate

### Known-deliberate — do not "fix" these

- **Emily runs `zai-org/glm-4.7:thinking`**, not glm-5 (owner-confirmed 2026-07-25).
  Per-instance model choice is expected, not drift.
- **`bot.py` stays a single file.** The whole deploy model depends on it. Recorded
  non-goal — don't propose splitting it.
- **`AUDIT-2026-07-10.md` records rejected claims.** Check before "fixing" a finding
  someone already ruled invalid.
- **`.claude/.runtime/` is gitignored.** Never commit it, never add it back.
- **PTB v21's `asyncio.get_event_loop()` workaround in `main()`** is intentional.
- **`nora.json` vs `caa16137-nora.json` have genuinely diverged** (14 data keys). They
  serve different frontends. Ask before syncing.

### Environment traps

- **`pytest` and `Pillow` are not installed** in a fresh remote container. Run
  `pip install -r telegram-companion-bot/requirements.txt pytest`, or the `bot-imports`
  eval skips and pytest can't run at all. Neither is a code bug.
- **Run `run-evals.sh` from the repo root.** From a subdirectory the relative path fails,
  and an `&&` chain can swallow the failure and commit anyway. Run it as its own command
  and read the last line.
- **Local green is evidence; CI on main is authority.**

### Vocabulary discipline — a real rule, not a style note

`CLAUDE.md` devotes a whole section to this. If a thing has a name in the code, use that
name verbatim: `GROUP_CHAIN_DECAY`, not "the dampening factor"; `_handle_group_message`,
not "the group entry point." A reader can grep an identifier; nobody can grep a phrase you
invented.

Something load-bearing with **no** name is a finding, not a licence to coin one. And
**never let a subagent's shorthand escape into a report or a diff** — agents coin terms
freely and compound each other's. Translate what an agent returns into repo terms and code
identifiers before relaying or acting on it. An agent's coinage is not a finding.

The sanctioned shorthand — the only terms needing no introduction — is the table in
`CLAUDE.md`: *the fleet, instance, the voiceprint, preset layer, the delivery gate,
break-test, the class, kill switch, Routine.*

### The rule that has been broken most interestingly

**Never edit a check, test, or eval to make it pass.** The one legitimate exception is
deliberately *widening* a check's scope, in the same commit, with the rationale written
down.

This is how the `/features` `ValueError` shipped past two rounds of tests (2026-08-02):
the tests asserted on **source text** instead of **calling the handler**. That's what the
`handlers-exercised` eval and the delivery gate's "a test that *calls* the `*_cmd`" clause
now exist to prevent.

And the subtler failure, C19/C20 (2026-08-07): the `ponytail` skill's own explicit text —
*"never lazy about understanding the problem… trace the whole thing first"* — was read,
agreed with, and **never checked against the specific diff being written.** The lesson is
in `CLAUDE.md` working principle #8: treat an explicit instruction as a literal constraint
to check the diff against, not a stance to agree with and move past.
