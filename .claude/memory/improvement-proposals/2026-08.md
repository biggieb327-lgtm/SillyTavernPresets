# Improvement proposal — 2026-08

## Pattern: source-assertion tests recur on functions the scanner can't see

`sweep.py source-assertion` (and the delivery gate built on the same
`_handler_coverage()`) only flags a test that mentions-but-never-calls a
function whose name ends `_cmd`. A source-assertion test on a helper function
called *from inside* a `_cmd` handler — not itself named `_cmd` — is invisible
to the scanner, so the exact failure it was built to prevent can still ship
through a helper.

## Occurrences (quoted, with dates/versions)

**#1 — CHANGELOG v2026-08-02.14** (the scanner's founding incident):
> "the two tests covering this command assert on its *source* — one checks
> the specs are 3-tuples, the other greps the handler text for `_is_admin`.
> Neither calls it." — `features_cmd`, a `*_cmd` function. Fixed by adding
> `sweep.py source-assertion`, scoped to `*_cmd` names only
> (`.claude/tools/sweep.py:552`, `:630`).

**#2 — CHANGELOG v2026-08-03.6**, found manually, not by the scanner:
> "`test_nanogpt_reports_the_model_too` read `gather_audit_data`'s *source*
> for the strings `SELFIE_MODEL` and `nanogpt`... A source assertion cannot
> fail for the reason the test exists; that is the family that shipped the
> `/features` `ValueError` past twelve green tests (v2026-08-02.4)."
> `gather_audit_data` is a plain helper (bot.py:13428), not a `*_cmd`
> function — `_handler_coverage()`'s `handlers` set (sweep.py:550-552)
> structurally excludes it. It is called directly from inside `audit_cmd`
> (bot.py:13527), so the failure sits one hop below the scanner's floor.

The author of #2 self-identified it as the same class, and it was caught only
because someone happened to touch that code that day — the standing eval
would not have flagged it.

## Proposed patch

`.claude/tools/sweep.py`, `_handler_coverage()` (line ~550): widen the
`handlers` set by one hop — after collecting `*_cmd`-named functions, also
walk each `*_cmd` function's body for direct `Call` nodes to other
module-level functions defined in `bot.py`, and add those names to
`handlers` too (still excluding lambdas/builtins/stdlib calls). This catches
`gather_audit_data` (called from `audit_cmd`) without widening to every
function in the file, which would false-positive on intentional source-scans
like `test_shared_prompt_hardcodes_no_character_specific_feature`
(deliberately reads `build_selfie_prompt`'s source, by design, per
v2026-08-03.2's changelog entry).

## Eval that would prove it worked

Extend the existing `source-assertion` eval / `gate_corpus` fixtures with a
case: a `*_cmd` handler that calls a helper function, a test that asserts on
the helper's source text via `inspect.getsource`/string literals without
calling the helper, and confirm `source_assertion()` now names the helper.
Break-test RED first against the current `sweep.py` (one-hop walk absent),
then GREEN after the patch — matching the repo's own break-test discipline
(`add-regression-eval`).
