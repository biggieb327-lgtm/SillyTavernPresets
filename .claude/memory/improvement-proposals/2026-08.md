# Improvement proposal — 2026-08

## Pattern: a per-instance location label can silently diverge from the character's own
canon, and the one check built for this class is scoped to miss the second occurrence.

**Occurrence 1 (CHANGELOG v2026-08-09.1 / operational-log 2026-08-09):** building
`tools/atlas_audit.py`, found priya's `setting.txt` and atlas are Bellevue while
`/audit` reports `Location: Seattle` (`WEATHER_LOCATION`) — "Found while building it,
not fixed here (per-instance `.env`, not code)."

**Occurrence 2 (CHANGELOG v2026-08-10.4 / operational-log 2026-08-10):** jules's
`WEATHER_LOCATION=Bellingham` with no coordinates defaulted to Seattle's lat/lon —
fixed with `_weather_config_warning` (label set away from default while coords stay
at theirs). The same release explicitly re-flags occurrence 1 as still open and
states why the new check can't see it: **"priya's label says Seattle while her
`setting.txt` and atlas are Bellevue. Her coordinates and label agree, so this check
stays quiet, correctly — that one is a content/config decision."**

No hook/eval prevented either: `_weather_config_warning` (bot.py) only compares
`WEATHER_LOCATION` against `WEATHER_LAT`/`WEATHER_LON`'s defaults, never against the
instance's own `setting.txt`, which is loaded into the prompt at runtime alongside it
and needs no network call to compare as text.

**Proposed patch:** `telegram-companion-bot/bot.py` — extend `_weather_config_warning`
(or add a sibling check feeding the same `_CONFIG_WARNINGS` list) to also flag when
none of `WEATHER_LOCATION`'s city-name tokens appear (case-insensitive) in the
instance's loaded `setting.txt`. Runs on the live bot at `/audit` time, where the real
`.env` and `setting.txt` are both already in memory — no TomTom key, no repo-only
limitation.

**Eval:** widen `TestWeatherConfigWarning`'s fleet matrix with a priya-shaped fixture
(`setting.txt` says Bellevue, `WEATHER_LOCATION=Seattle`) asserting the new warning
fires, and a matching-case fixture (`WEATHER_LOCATION=Bellevue`) asserting it stays
quiet — mirroring the existing "exactly `['jules']`" style pinned test.
