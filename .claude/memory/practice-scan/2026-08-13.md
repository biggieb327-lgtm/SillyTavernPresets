## 1. [fleet memory] Memory eviction and decay use creation age, never last-access

**Pointer:** "Memory Engineering: The System That Gives Your AI a Past"
(`https://emergingai.substack.com/p/memory-engineering-the-system-that`,
2026-08-08) — teaser promises "How to make memory update itself and forget
safely."

**Primary source:** Anthropic, Memory tool docs —
`https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool`
(fetched directly, HTTP 200), under "### Memory expiration":
> "Periodically delete memory files that haven't been accessed in a long
> time."

**What it would change:** bot.py's two memory-lifetime mechanisms both key
on **creation timestamp**, never on retrieval:
- `_evict_by_value` (bot.py:1957-1979) scores a memory by `(confidence, ts,
  insertion index)` where `ts` is set once at write time
  (`_memory_replace`, bot.py:2041: `{"ts": time.time(), "origin": ...}`) and
  is never touched again.
- The retrieval-ranking decay (`MEMORY_DECAY_HALFLIFE_DAYS`, bot.py:4464-
  4465, `_recency_weight(...ts...)`) reads that same static `ts`.

Grepped every write site to `_memory_meta[...]["ts"]` (bot.py:1295, 2041) —
neither the injection path (`assemble_messages` / `triggered_memories`) nor
any read path updates it. So a fact created six months ago and retrieved
in every single conversation since decays and competes for eviction
identically to one created the same day and never retrieved again — the
opposite of what the Anthropic guidance above is describing (expire by
*idleness*, not by *age*). This is exactly the shape `memory_ungrounded`'s
sibling counters exist to catch: not a bad extraction, but the fleet slowly
discarding facts it actually uses in favor of ones it doesn't, with no
signal that it's happening.

**Concrete change:** stamp `_memory_meta[...]["last_used"] = time.time()`
at the point a memory is actually injected into a reply (the same call
site that currently only reads `ts` for scoring), and have
`_recency_weight` / `_evict_by_value` decay against `last_used` (falling
back to `ts` for never-retrieved entries) instead of `ts` alone.

## 2. [fleet memory] The grounding guard checks a quote exists, not that the stored claim is faithful to it

**Pointer:** "Eval Engineering: A Beginner's Guide"
(`https://emergingai.substack.com/p/eval-engineering-a-beginners-guide`,
2026-08-04) — teaser: "response quality scored 83.9%, while faithfulness
to the tool results scored only 32.3%."

**Primary source:** Ragas, Faithfulness metric —
`https://raw.githubusercontent.com/explodinggradients/ragas/main/docs/concepts/metrics/available_metrics/faithfulness.md`
(fetched directly, HTTP 200; the docs.ragas.io host is on this session's
blocked list, GitHub raw is not):
> "A response is considered **faithful** if all its claims can be
> supported by the retrieved context."
The metric decomposes a response into individual claims and checks each
one against the retrieved context, rather than checking for one matching
span.

**What it would change:** `_quote_grounded` (bot.py:2642-2653) is the
entire grounding check behind both `memory_ungrounded` and
`note_ungrounded` (bot.py:4836, 4877). It is a single substring test — the
self-reported `memory_quote`/`user_note_quote` must appear verbatim
(case/whitespace-normalized) in the recent user lines. That proves the
*quote* is real; it proves nothing about whether the *stored fact* (`mem`/
`note`, a separate field the model also generates) only asserts what the
quote actually supports. A model could ground a real quote and still
attach an embellished or over-generalized claim to it, and the guard would
pass — the same gap Ragas' faithfulness score exists to catch (quality vs.
faithfulness are different axes, and only the second is checked here).

**Concrete change, scoped modestly:** not a per-extraction faithfulness
score (that's an added LLM call on the hot path, real cost for a low
per-turn defect rate). Instead: a periodic offline audit — sample N stored
memories/notes, and for each, ask a model "does `<mem>` follow only from
`<memory_quote>`, or does it add something the quote doesn't say?" Log a
new counter (`memory_unfaithful` / `note_unfaithful`, alongside the
existing `_ungrounded` pair) so the gap becomes measurable before deciding
whether it's worth a real-time check.
